## Start in 60 seconds

Start the server. With no config, you get one Issuer `default`, one public Client `test` and the Users `alice` and `bob`.

<Tabs syncKey="install">
<TabItem label="Docker" icon="seti:docker">

```sh frame="terminal" title="Terminal" wrap
docker run --rm -p 9000:9000 ghcr.io/schmas/fauxidc
```

</TabItem>
<TabItem label="Binary" icon="download">

```sh frame="terminal" title="Terminal (Apple silicon Mac)"
gh release download --repo schmas/fauxidc --pattern '*aarch64-apple-darwin.tar.gz'
tar -xzf fauxidc-*-aarch64-apple-darwin.tar.gz
sudo mv ./fauxidc-*-aarch64-apple-darwin/fauxidc /usr/local/bin/   # put it on your PATH
fauxidc
```

The [GitHub releases](https://github.com/schmas/fauxidc/releases) have archives for Linux (musl) and macOS, on x86_64 and arm64.

</TabItem>
<TabItem label="Cargo" icon="seti:rust">

```sh frame="terminal" title="Terminal" wrap
cargo install fauxidc --locked
fauxidc
```

This needs Rust 1.98 or newer.

</TabItem>
</Tabs>

Point your app at the Issuer URL `http://localhost:9000/default` with the client id `test`.
The [README](https://github.com/schmas/fauxidc#start-in-60-seconds) has all the install options.

</div>

## Mint a token without a browser

The Test API gives your test a signed token for any User, with the audience and claims that you need.

<div class="fx-split">
<div>

```sh frame="terminal" title="Request" wrap
curl -s http://localhost:9000/_mock/default/token \
  -H 'content-type: application/json' \
  -d '{"user": "alice", "audience": "https://api.example.test", "claims": {"roles": ["viewer"]}}'
```

```json title="Response (tokens trimmed)"
{
  "access_token": "eyJ0eXAiOiJhdCtqd3Qi...",
  "expires_in": 3600,
  "id_token": "eyJ0eXAiOiJKV1Qi...",
  "refresh_token": "eyJ0eXAiOiJydCtqd3Qi...",
  "scope": "openid profile email",
  "token_type": "Bearer"
}
```

</div>
<div>

```json title="access_token payload, decoded"
{
  "aud": "https://api.example.test",
  "auth_time": 1794959272,
  "client_id": "test-api",
  "email": "alice@example.com",
  "email_verified": true,
  "exp": 1794962872,
  "family_name": "Example",
  "given_name": "Alice",
  "iat": 1794959272,
  "iss": "http://localhost:9000/default",
  "jti": "75964861-dec8-4750-9f1a-c905db3ac839",
  "name": "Alice Example",
  "roles": ["viewer"],
  "scope": "openid profile email",
  "sub": "alice"
}
```

</div>
</div>

Try it: mint a token that expired one minute ago, and check that your API returns 401.

```sh frame="terminal" title="Terminal" wrap
curl -s http://localhost:9000/_mock/default/token -H 'content-type: application/json' -d '{"user": "bob", "expires_in": -60}'
```

## A real login page

Your app runs the real authorization code flow with PKCE. The user picks a User on the login page and the app gets real tokens.

<div class="fx-split fx-split-media">
<div>

```ini title=".env.development"
OIDC_ISSUER=http://localhost:9000/default
OIDC_CLIENT_ID=test
OIDC_SCOPE=openid profile email
```

The login page opens on the Custom user form (Subject and Claims).
Use the switch "Choose a configured User" to pick a User from a list.

</div>
<div>

<Media file="login-flow.gif" width={800} height={500} caption="The app sends the browser to fauxidc. Alice signs in. The app shows her ID token claims." />

```text title="Browser"
http://localhost:9000/default/debugger
```

## Break things on purpose

Inject a failure into one endpoint, and test how your app handles a provider outage.

<div class="fx-split fx-split-media">
<div>

```sh frame="terminal" title="Request" wrap
curl -s -X POST http://localhost:9000/_mock/default/fail-next \
  -H 'content-type: application/json' \
  -d '{"endpoint": "token", "status": 503, "count": 1}'
curl -s -i http://localhost:9000/default/token \
  -d 'grant_type=client_credentials&client_id=test'
```

```http title="Output" wrap
{"delay_ms":0,"endpoint":"token","error":"server_error","remaining":1,"status":503}
HTTP/1.1 503 Service Unavailable
content-type: application/json
cache-control: no-store

{"error":"server_error","error_description":"injected failure"}
```

</div>
<div>

<Media file="inject-failure.gif" width={800} height={500} caption="The dashboard sets a 503 failure on the token endpoint. The app shows the login error." />

</div>
</div>

Try it: remove all failures of the Issuer.

```sh frame="terminal" title="Terminal" wrap
curl -s -X DELETE http://localhost:9000/_mock/default/fail-next
```

## Use it from your AI coding agent

The repo gives your agent two skills and an `llms.txt`. Copy a prompt and change the names to match your project.

<div class="fx-split">
<div>

```text title="Prompt: configure a SPA" wrap
Our single-page app uses oidc-client-ts. Make it log in against a local fauxidc in Zero config:
start it with "docker run --rm -p 9000:9000 ghcr.io/schmas/fauxidc".
Use the authority http://localhost:9000/default, the public Client id "test", the code flow with PKCE (S256)
and the scope "openid profile email". Put these values in .env.development, not in the code.
Then open the app, log in as alice on the fauxidc login page and check that the app shows her email.
```

</div>
<div>

```text title="Prompt: write an integration test" wrap
Write an integration test for GET /api/orders of our API. Start fauxidc with examples/generic.toml
(Issuer "generic" at http://localhost:9000/generic). Before the request, mint an access token with the Test API:
POST http://localhost:9000/_mock/generic/token with the JSON body
{"user": "alice", "audience": "https://api.example.test", "claims": {"roles": ["viewer"]}}.
Send the access_token as a Bearer token and expect 200. Add a second test that mints a token with
"expires_in": -60 and expects 401. Configure the API to trust the issuer http://localhost:9000/generic
and to accept the access token header typ "at+jwt".
```

</div>
</div>

Try it: install the skills for one project (Claude Code).

```sh frame="terminal" title="Terminal" wrap
git clone https://github.com/schmas/fauxidc.git ~/src/fauxidc
mkdir -p .claude/skills
ln -s ~/src/fauxidc/skills/fauxidc .claude/skills/fauxidc
ln -s ~/src/fauxidc/skills/fauxidc-setup .claude/skills/fauxidc-setup
```
