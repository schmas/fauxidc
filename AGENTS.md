# AGENTS.md

This file gives guidance to coding agents (Claude Code, Codex and others) that work in this repository.

## Project Overview

fauxidc is a small OAuth 2.0 / OpenID Connect mock server for local development and integration tests.
It is a single static binary with no external infrastructure. It must never be used in production.
The repo is public: use neutral names only (`example-app`, `alice@example.com`, `example.test`).

Further reading: `docs/spec.md` (approved spec), `GLOSSARY.md` (domain terms), `docs/adr/` (decisions),
`docs/templates.md` (template context contract).

## Tech Stack

Only the pinned or unusual choices. The full crate table and the rejected crates are in `docs/spec.md` 13.2.

- Rust edition 2024. Toolchain 1.100.0, pinned in `rust-toolchain.toml`. MSRV 1.98 (`rust-version` in `Cargo.toml`).
- `tokio` with the `current_thread` runtime. `std::sync::Mutex`, no `parking_lot` or `dashmap`.
- `jsonwebtoken` with `rust_crypto`, not `aws_lc_rs`.
- No C code in the default build. The release build is a static musl binary (size limit 5 MiB).
- Optional `tls` feature: `rustls` with the `ring` provider (needs a C compiler).
- Tailwind CSS v4 and daisyUI v5 at dev time only, through `scripts/build-css.sh`. Not a Cargo dependency.
- `schemars` generates the config JSON Schema.
- Releases: `release-plz` in git-only mode. No crates.io publish.

A new dependency needs a reason in the PR.

## Commands

```bash
cargo build                                        # build
cargo run -- --config examples/generic.toml        # run
cargo test                                         # all tests (CI uses cargo nextest run)
cargo test <name>                                  # single test
cargo fmt --check                                  # format check
cargo clippy --all-targets -- -D warnings          # lint
cargo clippy --all-targets --features tls -- -D warnings   # lint with tls
cargo test --features tls                          # tests with tls
cargo build --release                              # release build
scripts/build-css.sh                               # rebuild assets/static/fauxidc.css
cargo run -q -- config --schema > schema/fauxidc.schema.json   # regenerate the schema
cd e2e/spa && npm ci && npx playwright test        # SPA exit test (docs/testing/m2-exit-test.md)
scripts/conformance.sh                             # OpenID conformance suite (conformance/README.md)
```

## Conventions

- One crate: `src/lib.rs` + `src/main.rs`. The lib exposes `fauxidc::Server::start(config).await`.
- Use the terms in `GLOSSARY.md` in code, docs and tests (Issuer, Client, User, Custom user, Strict mode, Lenient mode).
- Tests: unit tests next to the code. Integration tests in `tests/` with `tower::ServiceExt::oneshot`.
  Compatibility tests use the `openidconnect` crate.
- Errors: typed `thiserror` errors in the lib, `anyhow` only in `main.rs`. `OAuthError` implements `IntoResponse`.
- Commits: Conventional Commits. `release-plz` builds versions and the CHANGELOG from them.
- A change in `assets/templates/` or `assets/css/` runs `scripts/build-css.sh` and commits the new
  `assets/static/fauxidc.css` in the same commit. The CI job `css` checks it.
- A change to the config structs regenerates `schema/fauxidc.schema.json` in the same commit. A test checks it.
- A behavior change amends `docs/spec.md` in the same commit, and the user docs (`README.md`, `docs/`).
- Plans go in `.agents/plans/<date>-<slug>/`. `.agents/` is git-ignored.

## Rules

### Always

- Write the test first (TDD).
- Pass `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` before a commit.
- Record a significant design decision as an ADR in `docs/adr/`.

### Never

- `unsafe` code (`#![forbid(unsafe_code)]`).
- `unwrap()` / `expect()` outside tests and startup invariants (clippy denies them).
- Crates that need a C toolchain in the default build. The release build is a static musl binary.
- Names of real companies, client projects, internal hosts or email domains in code, docs, tests or commits.
- A CDN or new runtime network access. The pages and `cargo build` work offline.
  The only outbound request is the Client `jwks_uri` fetch that a config asks for.
